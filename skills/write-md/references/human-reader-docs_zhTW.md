# Human Reader Markdown Rules

- 本文件只在 Markdown 的目標讀者是人類時讀取。
- 人類文件的重點是可瀏覽、可導覽、容易建立心智模型。

## 適用情境

- README、使用者指南、功能文件、架構總覽、API 說明、設計提案、交付給團隊閱讀的技術文件。
- 內容目標是協助人快速理解背景、架構、流程、決策或使用方式。
- 文件會被放在 repo、Wiki、PR、Notion 或其他團隊知識庫中供人閱讀。

## 必要輸出規格

- 必須提供 `## 快速導覽` 或 `## 目錄`。
- 快速導覽必須使用 Markdown link，指向文件內的主要章節。
- 預設至少列出所有主要 `##` 章節；當文件很長或結構複雜時，可進一步補到重要的 `###`。
- 每個主要章節結尾必須提供返回開頭連結；預設用 `[返回開頭](#快速導覽)`。
- 若文件使用的是 `## 目錄` 而非 `## 快速導覽`，回頂 link 改成 `[返回開頭](#目錄)`。
- 每個主要章節與下一個章節之間，必須使用獨立一行的 `---` 水平分隔線。
- 預設把 `---` 放在該章節的返回開頭連結之後、下一個標題之前。
- 若調整標題名稱或章節順序，必須同步更新快速導覽與回頂 link，避免死連結或名稱不一致。

## 人類文件中的強制語氣

- 當給人類閱讀的繁體中文文件需要表達強制要求時，必須使用 `必須`。
- 當給人類閱讀的繁體中文文件需要表達強烈禁止時，必須使用 `嚴禁`。

## 圖表指南

- 必須讀取 [Mermaid 指南](mermaid-guide_zhTW.md)，依其中的人類文件要求與共用規則製作圖表。

## 典型結構

```markdown
# {功能 / 模組名稱}

## 快速導覽

- [概覽](#概覽)
- [架構](#架構)
- [流程](#流程)
- [核心元件](#核心元件)
- [注意事項](#注意事項)

## 概覽

- 目的。
- 範圍。
- 關鍵設計決策。

[返回開頭](#快速導覽)

---

## 架構

[架構圖]

[返回開頭](#快速導覽)

---

## 流程

[流程圖]

[返回開頭](#快速導覽)

---

## 核心元件

- {元件}：{說明}。

[返回開頭](#快速導覽)

---

## 注意事項

- 邊界條件。
- 設計限制。
- 待解決問題。

[返回開頭](#快速導覽)
```

- 不適用的章節直接省略，依需求增加領域專屬章節。
