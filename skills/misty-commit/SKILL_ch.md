# Misty Commit

## 選擇提交流程

1. 檢查使用者指示、對話 context、儲存庫規則、貢獻文件、適用的 skill、commit hook 與近期 commit 歷史，找出本次提交應遵循的指引。歷史只能作為清楚一致之慣例所涉及面向的證據；嚴禁將零散或混雜樣本推成強制規則，且明確指示優先。選擇流程前，先讀取適用的 commit skill。
2. 專案指引明確採用此 skill 的預設流程，且只補充專案輸入或動作時，讀取[預設提交指引](references/default-commit_ch.md)作為採用的基礎流程，在對應步驟套用補充。此明確委派不代表選用另一套獨立專案流程；嚴禁轉回委派的轉接入口，或以該入口存在為由略過已採用的基礎流程。此採用所涵蓋的決策，以採用流程為準，優先於從歷史推得的慣例。使用者明確限制與明訂的專案補充優先於基礎流程；受影響步驟前先解決衝突。
3. 否則，已有適用指引時，依該指引執行。嚴禁載入或套用預設指引的訊息語言、格式、amend 政策或 push 詢問。必要決策未定時，只詢問該項；細節缺漏不代表授權套用整套預設指引。
4. 否則，沒有適用 commit 指引時，讀取[預設提交指引](references/default-commit_ch.md)。使用者明確限制仍然有效；執行受影響步驟前，先解決衝突。

## 基本詢問與授權

1. 確認預定變更範圍與要求的結果：訊息或邊界審查、本地提交或對外發布。沿用已有答案與授權；只詢問無法從 context 確認的資訊，包括無關修改是否屬於範圍。
2. 只要求訊息或審查時，回傳提案，不改動 Git 狀態。提交前核對最終暫存內容、選定範圍與訊息；意圖不明時先釐清，嚴禁編造。
3. 只執行已授權的修改操作。建立 commit 的授權不包含 amend、push、tag 或 release。回報實際建立的 commit 與待完成步驟。

## 發布銜接

- 發布流程呼叫此 skill 時，沿用該流程選定的範圍與授權，將產生的 commit SHA 交回該流程。Commit 指引不能取代發布流程。
- 使用者要求發布時，依專案發布指引執行，包括明確委派給 `misty-release`；沒有指引時，若可用則使用 `misty-release`。嚴禁只因完成一般 commit 就啟動發布。

## 流程選擇範例

- 專案 commit skill 要求英文 subject 與工單前綴：依該 skill 執行，不載入預設指引。
- Local 入口明確採用 `misty-commit`，沒有另訂流程：使用已採用的預設指引，不能在兩個入口間反覆轉介。
- 沒有 commit 指引，使用者要求提交上傳重試：使用預設指引，只建立已授權的本地 commit，不打 tag 或發布。
