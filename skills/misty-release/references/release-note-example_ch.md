# Release Note 範例

- 此完整範例描述虛構上傳 CLI 從 2.8.1 升至 3.0.0 的發布；移除旗標屬於不相容變更。必須以已驗證的專案事實替換版號、能力、限制與遷移命令，並遵循專案的 note 語言。
- 依交付成果分組。只有發布確實需要時，才加入不相容變更與具體遷移步驟；省略空章節。

```markdown
# 3.0.0

## 新增能力

- 上傳遇到暫時連線失敗時，會自動重試最多三次。在重試次數內恢復連線後，無須手動重新執行命令；第三次重試仍失敗時，命令仍會回報失敗。

## 修復

- 檔名包含空白的檔案，現在會在目的地保留完整名稱。舊版 CLI 會在第一個空白處截斷檔名。

## 不相容變更

- 移除 `--retry-count` 旗標，改用 `--retries`。使用舊旗標的腳本會無法通過參數驗證，升級前必須更新。

## 遷移步驟

1. 將腳本與 CI 工作中的 `upload report.csv --retry-count 5` 改為 `upload report.csv --retries 5`。
2. 對測試目的地執行更新後的命令，確認上傳檔案保留預期名稱。
```

- 避免「更新 retry 模組」、「修正 parser」或「升版」等項目，因為它們沒有說明交付行為。沒有量測證據時，嚴禁宣稱上傳速度提升。
